# DAY 4 : Versioning of S3

Data protection and recovery are fundamental aspects of data management. It's essential to have systems in place to ensure that data can be recovered in case of accidental deletion or corruption. The DevOps team has received a requirement for implementing such measures for one of the S3 buckets they are managing

## Why is Versioning Needed
Resource = [S3 versioning AWS docs](https://docs.aws.amazon.com/AmazonS3/latest/userguide/versioning-workflows.html)

Its is need to add an object with same key, without overwritting, so it has versionID to differentiate between. The versionID is present even if the versioning is not not enabled to a S3 bucket and is value is `versionID = null`. 

When delete a object, it creates a version of the object as **Delete Marker**. To permanentely the object need to use that version's versionID to delete it permanently.

## Task
Enable the versioning to a specific S3.

## Steps

### Aws Console
  1. Navigate to the bucket in the S3
    
  2. Click the required bucket and go to properties tab
    ![alt text](<../Images/004-a.png>) 

  3. Click edit under the **Bucket Versioning** and select `ENABLE`
    ![alt text](<../Images/004-b.png>)

  4. Click Save Changes.
    ![alt text](<../Images/004-c.png>)

### AWS CLI

 ```sh
 aws s3api put-bucket-versioning --bucket bucket_name --versioning-configuration Status=Enabled		
 ```

## Key Learnings
- Use of S3 versioning is a best practice for data recovery and protection. 
- Uses soft delete concept which, where we can recover the data back when required.
