# Day 22: Configuring Secure SSH Access to an EC2 Instance

## Introduction

### What is SSH?

**Secure Shell (SSH)** is a secure network protocol used to remotely access and manage servers over an encrypted connection. It is the standard method for administering Linux servers in AWS and other cloud environments.

SSH encrypts all communication between the client and the server, ensuring that login credentials and data remain secure.

---

### What is SSH Key-Based Authentication?

SSH key-based authentication allows users to log in to a remote server **without using a password**.

Instead of entering a password each time, the client proves its identity using a **private key**, while the server verifies it using the corresponding **public key** stored in the user's `authorized_keys` file.

This method is more secure than password authentication and is widely used in DevOps and cloud environments.

---

## Why Use SSH Keys?

SSH keys provide secure and convenient access to remote Linux servers.

Common benefits include:

- Eliminates the need to enter passwords repeatedly.
- Stronger security than password authentication.
- Enables secure automation using scripts and tools like Ansible.
- Reduces the risk of brute-force password attacks.
- Standard authentication method for AWS EC2 instances.

---

## How SSH Key Authentication Works

```text
Generate SSH Key Pair
        │
        ▼
Private Key (Client)
Public Key (Server)
        │
        ▼
Copy Public Key to EC2
(~/.ssh/authorized_keys)
        │
        ▼
SSH Connection Request
        │
        ▼
Server Verifies Public Key
        │
        ▼
Passwordless Login Successful
```

# Task

Create an EC2 instance and configure passwordless SSH access from the **aws-client** host.

| Setting | Value |
|----------|-------|
| Instance Name | `datacenter-ec2` |
| Instance Type | `t2.micro` |
| Operating System | Any Linux AMI |
| SSH Key Name | `id_rsa` |
| Key Location (aws-client) | `/root/.ssh/id_rsa` |

The public key generated on the **aws-client** host should be added to the **root** user's `authorized_keys` file on the EC2 instance.

# Steps (AWS Management Console)

## Step 1: Launch the EC2 Instance

1. Sign in to the **AWS Management Console**.
2. Navigate to:

```text
Services → EC2
```

Click:

```text
Launch Instance
```

Configure the instance:

| Setting | Value |
|----------|-------|
| Name | `datacenter-ec2` |
| AMI | Ubuntu Server or Amazon Linux |
| Instance Type | `t2.micro` |
| Key Pair | Create or select any existing key pair |
| Security Group | Allow SSH (Port 22) |

Click:

```text
Launch Instance
```

Wait until the instance reaches the **Running** state.

---

## Step 2: Generate an SSH Key on aws-client

On the **aws-client** host, check whether the SSH key already exists:

```sh
ls -l /root/.ssh/id_rsa
```

If the file does not exist, generate a new RSA key pair:

```sh
ssh-keygen -t rsa -f /root/.ssh/id_rsa -N ""
```

This creates:

```text
/root/.ssh/id_rsa
/root/.ssh/id_rsa.pub
```

---

## Step 3: Copy the Public Key to the EC2 Instance

Display the public key:

```sh
cat /root/.ssh/id_rsa.pub
```

Copy the output.

Connect to the EC2 instance using its existing login method.

Create the `.ssh` directory if it does not already exist:

```sh
mkdir -p /root/.ssh
```

Append the copied public key to:

```text
/root/.ssh/authorized_keys
```

Example:

```sh
echo "<PASTE_PUBLIC_KEY_HERE>" >> /root/.ssh/authorized_keys
```

---

## Step 4: Set Correct Permissions

On the EC2 instance, run:

```sh
chmod 700 /root/.ssh
```

```sh
chmod 600 /root/.ssh/authorized_keys
```

---

## Step 5: Test Passwordless SSH

From the **aws-client** host, connect using the private key:

```sh
ssh -i /root/.ssh/id_rsa root@<EC2_PUBLIC_IP>
```

If configured correctly, SSH should log in without prompting for a password.

# Things to Remember

- The **private key (`id_rsa`) must never be shared**.
- Only the **public key (`id_rsa.pub`)** should be copied to the remote server.
- The public key must be added to the user's `~/.ssh/authorized_keys` file.
- The `.ssh` directory should have **700** permissions, and `authorized_keys` should have **600** permissions.
- AWS security groups must allow inbound SSH (Port 22) from the required source IP.
- SSH key-based authentication is more secure than password authentication and is the recommended approach for EC2 instances.
