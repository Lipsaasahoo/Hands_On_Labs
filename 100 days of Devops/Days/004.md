# Day 4: Script Execution Permissions

## Task
Your task is to grant executable permissions to the /tmp/xfusioncorp.sh script on App Server 1. Additionally, ensure that all users have the capability to execute it.

## Why we need this

There can be several files and folders in the linux server that need not be available to all the users and groups. So wee need file permissions management to control who can access what.

By default the linux gives basic file and folder access and operation permission. But based on our / organization use case we can modify the permissions. This is done using `chmod`

**File Permission Basics**

Each file in Linux has 3 types of permission:
 - Read (r) : to read/view the file
 - Write (w) : to write / update the contents in file
 - Execute (x) : to execute the script file

Permissions are set for 3 user categories:
 - Users (u) : the one who creates the file
 - Groups (g) : user that belong to a group
 - Others (o) : all other users

Each categories can have its own combination of r,w,x.

**Two way of using the command**

1. Symbolic way using the letters

```sh
chmod u=rwx,g=rx,o=r sample.sh
```
  This gives the following permission:
    - Users (u) : read, write, execute
    - Group (g) : read and execute
    - Others (o) : read only

2. Numeric(Octal) way where each permission is represented by a digit
    - read : 4
    - write : 2
    - execute : 1

    we need to sum up each user category permission and make a 3-digit no to set permissions

```sh
chmod 754 sample.sh
```
    where:
        - 7 (User) : 4 + 2 + 1 = rwx
        - 5 (Group) : 4 + 0 + 1 = r_x
        - 5 (Others) : 4 + 0 + 0 = r_ _

## Steps

1. SSH into the required server

2. Check the file path we are in the server
   - `/` : root directory
   - `~` : Persons home directory
   - cd into the directory where the file is present and whose permissions need to be set.

3. Run a command to check the current permission of the file.
    ```sh
    ls -la
    ```
    > output : ----------  1 root root   40 Jul  6 17:08 xfusioncorp.sh

4. Run the command to modify the permission
    ```sh
    sudo chmod 755 script-file-name
    ```
5. Verify the result
    ```sh
    ls -la
    ```
    > output : -rwxr-xr-x  1 root root   40 Jul  6 17:08 xfusioncorp.sh

## Key Learnings
- Got the basic understanding of the file permissions
- Best security practices is to grant the minimum required permissions
- chmod 777 gives full access (Dangerous - avoid)
- chmod 600 private file
- chmod 755 standard executable file for scripts
- chmod 644 standard file (default)
