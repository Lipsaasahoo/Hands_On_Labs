# Day 7: Linux SSH Password-less Authentication

## Introduction

### What is SSH?

**SSH (Secure Shell)** is a secure network protocol used to remotely access and manage Linux servers over an encrypted connection. It allows administrators to execute commands, transfer files, and perform system administration tasks securely.

Normally, SSH authentication requires entering a password every time a connection is established.

---

### What is Password-less SSH Authentication?

Password-less SSH authentication allows users to log in to a remote server **without entering a password**. Instead of passwords, SSH uses a **public-private key pair** for authentication.

The process works as follows:

- The **private key** remains securely on the client machine.
- The **public key** is copied to the remote server.
- During login, the server verifies that the client possesses the matching private key.
- If the keys match, access is granted automatically.

This method is both **more secure** and **more convenient** than password-based authentication.

---

### Why is Password-less SSH Needed?

In many organizations, automation scripts perform administrative tasks across multiple Linux servers.

Examples include:

- Deploying applications
- Collecting server logs
- Running backup scripts
- Monitoring server health
- Installing updates
- Executing maintenance tasks

If every SSH connection required a password, automation would fail because scripts cannot manually enter passwords.

By configuring password-less SSH authentication, scripts can securely connect to remote servers without user intervention.

In this task, the **thor** user on the **Jump Host** must be able to access each application server using the corresponding sudo user without entering a password.

---

### How SSH Key Authentication Works

```
Jump Host (thor)
       │
       │ Generates SSH Key Pair
       ▼
+---------------------------+
| Private Key (id_rsa)      |  ← Stays on Jump Host
+---------------------------+

               │

               ▼

+---------------------------+
| Public Key (id_rsa.pub)   |
+---------------------------+

               │
      Copied to Remote Server

               ▼

~/.ssh/authorized_keys

               │

               ▼

SSH Login Without Password
```

# Task

Configure password-less SSH authentication so that:

- The **thor** user on the **Jump Host** can SSH into every application server.
- Authentication should use SSH keys instead of passwords.
- Each server should be accessed using its respective sudo user.

Example:

| Server | User |
|--------|------|
| App Server 1 | `tony` |
| App Server 2 | `steve` |
| App Server 3 | `banner` |

---

# Steps

## Step 1: Log in to the Jump Host

Log in as the **thor** user.

Verify the current user:

```sh
whoami
```

Expected output:

```text
thor
```

---

## Step 2: Generate an SSH Key Pair

Check whether an SSH key already exists:

```sh
ls ~/.ssh
```

If no key pair exists, generate one:

```sh
ssh-keygen -t rsa
```

When prompted:

```text
Enter file in which to save the key:
```

Press **Enter** to use the default location.

For the passphrase prompts:

```text
Enter passphrase:
```

Press **Enter** twice to leave it empty.

This creates two files:

| File | Purpose |
|------|---------|
| `~/.ssh/id_rsa` | Private key (keep secret) |
| `~/.ssh/id_rsa.pub` | Public key (shared with remote servers) |

---

## Step 3: Copy the Public Key to Each App Server

Copy the public key to each application server using the corresponding user.

Example:

### App Server 1

```sh
ssh-copy-id tony@stapp01
```

### App Server 2

```sh
ssh-copy-id steve@stapp02
```

### App Server 3

```sh
ssh-copy-id banner@stapp03
```

When prompted:

```text
Are you sure you want to continue connecting?
```

Type:

```text
yes
```

Then enter the user's password.

The public key is copied to:

```text
~/.ssh/authorized_keys
```

on the remote server.

---

## Step 4: Verify Password-less Authentication

Test the SSH connection.

Example:

```sh
ssh tony@stapp01
```

If configured correctly, the login should occur **without prompting for a password**.

Repeat the verification for the remaining servers:

```sh
ssh steve@stapp02
```

```sh
ssh banner@stapp03
```

All connections should authenticate successfully using the SSH key.

---

## Step 5: Confirm Successful Login

Verify the logged-in user on each server:

```sh
whoami
```

Expected outputs:

App Server 1

```text
tony
```

App Server 2

```text
steve
```

App Server 3

```text
banner
```

This confirms that password-less SSH authentication is working correctly.

---

# How It Works

```
             Jump Host
              (thor)
                 │
                 │ SSH
                 ▼
        Uses Private Key
        ~/.ssh/id_rsa
                 │
                 ▼
        App Server (tony)
   ~/.ssh/authorized_keys
                 │
      Public Key Matches
                 │
                 ▼
      Login Successful
```

The **private key** never leaves the Jump Host.

Only the **public key** is stored on the remote servers, making the authentication process secure.
