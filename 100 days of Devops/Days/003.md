# Day 3: Secure Root SSH Access

## Task
To disable direct SSH root login in application servers

## Thought Process of Why this is needed

On Linux system, the `root` account has unrestricted administrative previleges. 

The attackers can use brute force to guess the password of the root account and can cause malicious activity since the username `root` is well known.

No way to trach individual users loging as root users.

Best Practice:
- Users log in with their own account
- Use adimin previleges via `sudo`

**Example**: On cloud servers like AWS, by default the providers disable root SSH login.

## Steps

1. Connect to each App server via SSH

    ```sh
    ssh username@server_ip
    ssh username@server_name
    ```

2. Edit the `sshd_config` file

    ```sh
    sudo vim /etc/ssh/sshd_config
    ```
    Press `i` to get **INSERT** mode and find the like PermitRootLogin yes

    Change it to PermitRootLogin no

3. Save and close the file

    Press `ESC` --> type `:wq!` --> `ENTER`

4. Restart SSH Service

    ```sh
    sudo systemctl restart sshd
    ```

5. Verify Output

    - Try loging in to as root
      Output: Permission Denied

    - Check via sudo sshd -T | grep permitrootlogin
      Output: permitrootlogin no

6. Repeat the same step for all the App servers

## Key Learnings

- Disabling direct SSH root access is a ***fundamental server hardening step***.

- Verify the result, `sshd -T` is asefty check is any typo or syntax error in the sshd_config file. 

- Always check the configuration and then restart the SSH service. If we restart the SSH service with broken configuration then we might lock ourself out of the server

- Use `sudo` to get admin previlages instead of direct ssh root access.
